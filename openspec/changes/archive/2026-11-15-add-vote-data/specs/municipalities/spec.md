# Spec Delta

## Purpose

The list of municipalities that all data files of the app use: where it comes from, the date it
is valid for, and how the entries that are no municipality and the municipalities without a
result are told apart from it.

The sources, each public, and the step that regenerates the list from them:

- **BFS register of municipalities**: Federal Statistical Office,
  `https://www.agvchapp.bfs.admin.ch/api/communes/snapshot?date=<dd-mm-yyyy>`, the
  municipalities, districts and cantons that existed on a date.
- **BFS vote-day files** (see the `vote-data` capability): each states the reference date of
  the list of municipalities its results are given on; on 2026-11-14 that is 2026-01-01 in
  every file.
- **Regenerated by** the update command of the pipeline (`pipeline/README.md`).

The figures in the scenarios are those of `investigations/data-sources.md`.

## ADDED Requirements

### Requirement: One list of municipalities for all votes

All covered votes SHALL use one list of municipalities: the one of the reference date that the
BFS vote-day files state. The results of a vote held before a merger are those the BFS gives
for the municipality of the reference date. When the vote-day files do not all state the same
reference date, or one states none, the update SHALL stop with an error that names the files
and their dates, and SHALL write no data file.

#### Scenario: The reference date on 2026-11-14

- **GIVEN** the sources as they were on 2026-11-14
- **WHEN** the list of municipalities and the list of votes are read
- **THEN** each gives 2026-01-01 as the reference date

#### Scenario: Two vote days on different lists

- **GIVEN** BFS files of which one states the reference date 2027-01-01 and the others
  2026-01-01
- **WHEN** the update command runs
- **THEN** it stops with an error that names that file and both dates, and writes no data file

#### Scenario: A vote from before a merger

- **WHEN** the file of the vote with id 5670, of 2013-03-03, is read
- **THEN** its entries are municipalities of the list of 2026-01-01, 2,103 of them, although
  2,408 municipalities existed on 2013-01-01 (`investigations/data-sources.md`, "Answers", 3)

### Requirement: The list of municipalities

The pipeline SHALL write the list of municipalities with its reference date. It SHALL hold
every municipality that the BFS register gives for that date, each once, with its number, its
name and the canton it belongs to on that date. When the register cannot be read for that date,
gives a number twice, or gives a municipality without a name or without one of the 26 cantons,
the update SHALL stop and write no data file.

#### Scenario: The list on 2026-11-14

- **GIVEN** the sources as they were on 2026-11-14
- **WHEN** the list of municipalities is read
- **THEN** it has 2,110 municipalities in 26 cantons, among them number 1, "Aeugst am Albis",
  in ZH

#### Scenario: A municipality that has changed canton

- **WHEN** Moutier is read from the list of municipalities of 2026-01-01
- **THEN** its number is 6831 and its canton is JU, the canton it belongs to on the reference
  date

#### Scenario: The register gives a number twice

- **GIVEN** an answer of the register in which one number appears for two municipalities
- **WHEN** the update command runs
- **THEN** it stops with an error that names the number, and writes no data file

### Requirement: Every entry is known and counted once

Every entry of a vote SHALL be a municipality of the list or the Swiss abroad of its canton. An
entry with any other number SHALL stop the update with an error that names the vote and the
number. A number that appears twice among the entries of a vote SHALL stop the update in the
same way. An entry SHALL never be dropped to make a vote pass.

#### Scenario: Every municipality at most once

- **WHEN** the entries of the vote with id 5960 are read
- **THEN** 2,103 of them are municipalities of the list, each a different one, and 12 are Swiss
  abroad

#### Scenario: An unknown municipality

- **GIVEN** a BFS file in which a vote has an entry with the number 7999, which is neither on
  the list of municipalities nor a number of the Swiss abroad
- **WHEN** the update command runs
- **THEN** it stops with an error that names the vote and the number 7999, and writes no data
  file

#### Scenario: A municipality twice

- **GIVEN** a BFS file in which a vote has two entries with the number 1
- **WHEN** the update command runs
- **THEN** it stops with an error that names the vote and the number 1, and writes no data file

### Requirement: The Swiss abroad are entries of their own

Where a canton counts its Swiss abroad apart from its municipalities, the BFS file has an entry
for them with a number from 9010 to 9260: 9000 plus ten times the position of the canton in the
order of the Federal Constitution. Such an entry SHALL be kept as an entry of that canton,
marked as Swiss abroad and not as a municipality. The list of municipalities SHALL name, per
canton, the number of this entry. An entry in this range under another canton SHALL stop the
update.

#### Scenario: The Swiss abroad of a canton

- **WHEN** the entries of the canton ZH are read from the file of the vote with id 5960
- **THEN** there are 161: 160 municipalities and the entry 9010, the Swiss abroad, with 3,596
  yes and 4,939 no votes (`investigations/data-sources.md`, "Reference data for the
  calculation")

#### Scenario: The cantons that count them apart

- **GIVEN** the sources as they were on 2026-11-14
- **WHEN** the list of municipalities is read
- **THEN** it names an entry of the Swiss abroad for 12 cantons: ZH 9010, LU 9030, UR 9040,
  FR 9100, BS 9120, AI 9160, SG 9170, AG 9190, TG 9200, VD 9220, VS 9230 and GE 9250

#### Scenario: A canton that began later

- **WHEN** the files of the votes with the ids 5670, of 2013-03-03, and 5960, of 2016-02-28,
  are read
- **THEN** the first has the Swiss abroad of 11 cantons and no entry 9010, and the second has
  those of 12 cantons (`investigations/data-sources.md`, "Answers", 2)

#### Scenario: The number of another canton

- **GIVEN** a BFS file in which the entry 9010 is among the entries of the canton BE
- **WHEN** the update command runs
- **THEN** it stops with an error that names the vote, the number and the canton, and writes no
  data file

### Requirement: Municipalities without a result

A municipality of the list that has no entry in a vote has no result of its own there: its
votes are counted with another municipality's. The file of each vote SHALL name these
municipalities by their numbers. Such a municipality SHALL NOT appear as an entry, neither with
zeros nor with another municipality's figures. Where its votes are counted is not recorded.

#### Scenario: The municipalities without a result in 2016

- **WHEN** the file of the vote with id 5960, of 2016-02-28, is read
- **THEN** it names seven municipalities without a result: 389 Meienried, 408 Hellsau, 422 Rüti
  bei Lyssach, 535 Deisswil bei Münchenbuchsee, 629 Oberhünigen, 868 Jaberg and 877
  Niedermuhlern, all of the canton BE (`investigations/data-sources.md`, "Answers", 2)

#### Scenario: The municipalities without a result in 2025

- **WHEN** the file of the vote with id 6790, of 2025-09-28, is read
- **THEN** it names five municipalities without a result: 389, 408, 535, 629 and 877

#### Scenario: Entries and municipalities without a result make up the list

- **WHEN** the file of any covered vote is read
- **THEN** every municipality of the list is either exactly one entry or named as without a
  result, and never both
