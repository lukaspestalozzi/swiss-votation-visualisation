# vote-data Specification

## Purpose

The data files on the national popular votes that the pipeline produces for the app: which votes
they cover, what they hold, where each figure comes from, the checks they pass, and how a new
vote day is added.

The sources, each public, and the step that regenerates the files from them:

- **BFS vote-day files**: Federal Statistical Office, one file per vote day,
  `https://ogd-static.voteinfo-app.ch/v1/ogd/sd-t-17-02-<yyyymmdd>-eidgAbstimmung.json`. Each
  file states the reference date of its list of municipalities; on 2026-11-14 that is 2026-01-01
  in every file.
- **Federal Chancellery**: the national results the Federal Council validated, as linked data,
  `https://lindas.admin.ch/query`, data set
  `https://politics.ld.admin.ch/political-rights/popular-vote/`. It has no municipalities.
- **Regenerated by** the update command of the pipeline (`pipeline/README.md`).

The figures in the scenarios are those of `investigations/data-sources.md`.

## Requirements

### Requirement: The votes covered

The data files SHALL cover every national popular vote since 2013-01-01 for which the BFS
vote-day file has a complete result: the vote is closed and every one of its entries is
counted. A vote without a complete result SHALL be left out, and the update command SHALL name
it in its output. A vote that the Federal Chancellery has validated and that has no complete
result in the BFS file SHALL stop the update.

  über die Familienpolitik", and number 568, "Volksinitiative «gegen die Abzockerei»"

- **WHEN** the update command runs

- **WHEN** the update command runs

### Requirement: The list of votes

The pipeline SHALL write one list of all covered votes, ordered by date and then by id. For
each vote it SHALL hold: the id the BFS gives it, the number the Federal Chancellery gives it,
the date, the kind, the title in German, French and Italian as the BFS gives it, whether the
vote is validated, the result, the Chancellery's reference and note, and the sums of the
vote's entries. A title that is missing or empty in one of the three languages SHALL stop the
update.

- **WHEN** the vote with id 5960 is read from the list of votes
- **THEN** its number is 596, its date is 2016-02-28, its kind is `popular-initiative`, and its
  German title is "Volksinitiative «Für Ehe und Familie - gegen die Heiratsstrafe»"

- **THEN** the ids 6821, 6822 and 6823 are three votes, and each has the number 682

- **GIVEN** a BFS file in which a vote has no Italian title
- **WHEN** the update command runs
- **THEN** it stops with an error that names the vote and the language, and writes no data file

### Requirement: The kind of a vote

The kind of a vote SHALL be taken from the code of the BFS file: 1 `mandatory-referendum`,
2 `optional-referendum`, 3 `popular-initiative`, 4 `initiative-with-counter-proposal`,
5 `counter-proposal`, 6 `tie-break-question`. These are the names of the `result-calculation`
capability. Any other code SHALL stop the update. The update SHALL also stop when the BFS
file's own statement on the double majority contradicts the code: needed for every code except
2, not needed for 2.

#### Scenario: The three usual kinds

- **WHEN** the votes with the ids 5670, 5950 and 5960 are read from the list of votes
- **THEN** their kinds are `mandatory-referendum`, `optional-referendum` and
  `popular-initiative`

#### Scenario: The initiative with a counter-proposal

- **WHEN** the votes with the ids 6821, 6822 and 6823 are read from the list of votes
- **THEN** their kinds are `initiative-with-counter-proposal`, `counter-proposal` and

- **GIVEN** a BFS file in which a vote has the code 7
- **WHEN** the update command runs
- **THEN** it stops with an error that names the vote and the code, and writes no data file

#### Scenario: The code and the double majority contradict each other

- **GIVEN** a BFS file in which a vote has the code 2 and is said to need the double majority
- **WHEN** the update command runs
- **THEN** it stops with an error that names the vote, and writes no data file

### Requirement: The result of a vote

The result of a validated vote SHALL be the Federal Chancellery's: the yes votes, the no votes,
the cantonal votes in favour and against, and whether the vote passed. A vote is validated when
the Chancellery gives its yes and its no votes. The result of any other vote SHALL be the one
of the BFS file, and the vote SHALL be marked as not validated. Cantonal votes SHALL be held as
the source of the result gives them, and as none where it gives none. A tie-break question
SHALL have no verdict.

### Requirement: The Chancellery's reference and note

For a validated vote, the list of votes SHALL hold the reference to the official publication of
the result, in German, French and Italian, as the Federal Chancellery gives it; a validated
vote without it SHALL stop the update. Where the Chancellery gives a note on a vote, the list
SHALL hold it in the same three languages, unchanged. A vote without a note, and a vote that is
not validated, SHALL hold none.

### Requirement: The entries of a vote

The pipeline SHALL write one file per covered vote with all its entries, grouped by canton. An
entry SHALL hold, as the BFS file gives them: its number, the registered voters, the ballots
cast, the valid ballots, the yes votes and the no votes. Turnout SHALL NOT be stored: it is the
ballots cast divided by the registered voters. The registered voters and the ballots cast are
the BFS's figures; they are not compared with the Federal Chancellery's.

#### Scenario: The entries of a vote

- **WHEN** the file of the vote with id 5960 is read
- **THEN** it has 2,115 entries in 26 cantons: 2,103 municipalities and the Swiss abroad of 12
  cantons

#### Scenario: One entry

- **WHEN** the entry of Aeugst am Albis, number 1, is read from the file of the vote with id
  5960
- **THEN** it is in the canton ZH, with 1,398 registered voters, 999 ballots cast, 982 valid
  ballots, 432 yes votes and 550 no votes

#### Scenario: Turnout

- **WHEN** the turnout of the vote with id 5960 is calculated from the sums of its entries,
  3,354,019 ballots cast and 5,302,873 registered voters
- **THEN** it is 63.2491%, within 0.00005 percentage points

### Requirement: Every count is a whole number from zero

The update SHALL stop when a count of an entry, of a canton or of a vote in a source is
missing, is not a whole number, is given as text, or is below zero. The error SHALL name the
source file, the vote, the entry and the figure. A value SHALL never be replaced by zero,
skipped, rounded or converted. The update SHALL also stop when, in an entry, the valid ballots
exceed the ballots cast, or the ballots cast exceed the registered voters.

#### Scenario: A missing value

- **GIVEN** a BFS file in which the yes votes of one entry of a complete vote are missing
- **WHEN** the update command runs
- **THEN** it stops with an error that names the file, the vote, the number of the entry and
  "yes votes", and writes no data file

- **GIVEN** a BFS file in which the no votes of one entry are 550.0
- **WHEN** the update command runs
- **THEN** it stops with an error that names the file, the vote, the entry and "no votes", and

- **WHEN** the update command runs
- **THEN** it stops with an error that names the file, the vote, the entry and "registered

- **WHEN** the update command runs
- **THEN** it stops with an error that names the file, the vote and the entry, and writes no

### Requirement: The valid ballots and the votes

For every entry of a vote of the kinds `mandatory-referendum`, `optional-referendum` and
`popular-initiative`, the valid ballots SHALL equal the yes votes plus the no votes, exactly;
otherwise the update SHALL stop. For the three other kinds, a voter may leave a question
unanswered: there the valid ballots SHALL be at least the yes votes plus the no votes, and the
update SHALL stop when they are fewer.

#### Scenario: A usual vote

- **WHEN** the sums of the entries of the vote with id 5960 are read
- **THEN** the valid ballots are 3,273,376, exactly the 1,609,152 yes votes plus the 1,664,224
  no votes

- **GIVEN** the sources as they were on 2026-11-14
- **WHEN** the sums of the entries of the vote with id 6821 are read
- **THEN** the valid ballots are 3,081,025, and the yes votes plus the no votes are 3,028,036

  votes and 549 no votes
- **WHEN** the update command runs
- **THEN** it stops with an error that names the file, the vote and the entry, and writes no
  data file

### Requirement: The entries add up to the figures of the BFS

For every covered vote and each of the five counts (registered voters, ballots cast, valid
ballots, yes votes, no votes), the entries SHALL sum exactly to the figure the BFS file gives
for Switzerland. Otherwise the update SHALL stop with an error that names the vote, the count
and both figures. The list of votes SHALL hold these five sums for each vote.

#### Scenario: The sums of a vote

- **WHEN** the vote with id 5960 is read from the list of votes
- **THEN** the sums of its entries are 5,302,873 registered voters, 3,354,019 ballots cast,
  3,273,376 valid ballots, 1,609,152 yes votes and 1,664,224 no votes
  (`investigations/data-sources.md`, "Reference values")

#### Scenario: A merged municipality is counted once

- **WHEN** the yes votes of all entries of the vote with id 5960 are added up
- **THEN** the sum is 1,609,152, not the 1,622,968 of the predecessor (`docs/roadmap.md`,
  failure mode 3)

#### Scenario: The entries do not add up

- **GIVEN** a BFS file in which the entries of a vote sum to one yes vote more than the file
  gives for Switzerland
- **WHEN** the update command runs
- **THEN** it stops with an error that names the vote, "yes votes" and both figures, and writes
  no data file

### Requirement: An entry counts for the canton it voted in

An entry SHALL be grouped under the canton whose result it was part of in that vote. A
municipality that has changed canton SHALL be named, with its earlier canton and the last day
it belonged to it, in a list of changes of canton kept in the pipeline. For every vote and
every canton, the entries of the canton SHALL sum exactly to the canton's five counts in the
BFS file; otherwise the update SHALL stop with an error that names the vote, the canton, the
count and both figures.

### Requirement: The entries agree with the official result

For every validated vote, the yes votes and the no votes of the entries SHALL each sum exactly
to the Federal Chancellery's figure, unless the difference is in the pipeline's list of known
differences with the vote, the count and both figures. A difference that is not listed SHALL
stop the update, and so SHALL a listed difference that the sources no longer show as listed.
The list of votes holds both figures, so a listed difference can be read from it.

#### Scenario: A vote that agrees

- **WHEN** the vote with id 5960 is read from the list of votes
- **THEN** the yes votes and the no votes of its result equal the sums of its entries:
  1,609,152 and 1,664,224

### Requirement: The two sources agree on the verdict and the cantonal votes

For every validated vote other than a tie-break question, the Federal Chancellery's verdict
SHALL equal the one of the BFS file, and where both sources give cantonal votes, they SHALL be
equal in favour and against. Otherwise the update SHALL stop with an error that names the vote
and both values.

#### Scenario: The sources agree

- **WHEN** the update command runs
- **THEN** it stops with an error that names the vote and both verdicts, and writes no data file

### Requirement: The calculation gives the result of every vote

The checks SHALL run the `result-calculation` capability over the committed data files. For
every vote whose kind is calculated, with all entries of its file: the yes and the no votes
SHALL equal the sums in the list of votes; the cantonal votes SHALL equal those of the result
where it has them; the verdict SHALL equal the one of the result. A validated vote SHALL have
cantonal votes in its result exactly when its kind needs both majorities.

### Requirement: The record of the sources

The pipeline SHALL write, with the data files, a record of every source file they were made
from: its address, its size, its checksum, for a BFS vote-day file the time the file states for
itself, and for an answer to a query the query it answers. The data files hold no time of the
run: an update with unchanged sources SHALL leave every data file unchanged, byte for byte.

#### Scenario: The record names every source file

- **GIVEN** the sources as they were on 2026-11-15
- **WHEN** the record of the sources is read
- **THEN** it names 45 BFS vote-day files, the answer of the Federal Chancellery, the answer of
  the BFS register of municipalities, the register's three answers with the boundaries of the
  municipalities, of the cantons and of Switzerland, and the BFS ThemaKart set 2026, each with
  its address, size and checksum
- **AND** for the characteristics it names 49 answers of the BFS statistics API (STAT-TAB) to a
  query and its description of the table of the elections, the register's lists of 2000-12-05,
  2023-01-01 and 2025-04-06 and its correspondences from each of them to 2026-01-01, and
  swisstopo's swissBOUNDARIES3D of 2026-01, each with its address, size and checksum, and each
  answer of STAT-TAB and of the Federal Chancellery with its query

#### Scenario: A second run changes nothing

- **GIVEN** the update command has run and the sources have not changed since
- **WHEN** it runs again
- **THEN** `git status` shows no changed data file

### Requirement: Adding a vote day

One command, run by hand, SHALL bring the data files up to date: it downloads the sources,
runs every check of the pipeline, and writes all data files, adding a new vote day and
replacing a result once validated. When a source cannot be reached or a check fails, it SHALL
say which, exit with a status other than zero, and leave every data file as it was. The
calculation's check runs with the unit tests; `pipeline/README.md` SHALL give the procedure.

### Requirement: No vote is lost

An update SHALL NOT remove a vote from the data files. When a vote that the data files hold is
not among the votes the sources give, the update SHALL stop with an error that names each such
vote by its id and date, and SHALL leave every data file as it was.

  Federal Chancellery without the vote day 2026-03-08

  before
